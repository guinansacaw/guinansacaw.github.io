Backend automation case: from ERP events to automated customer feedback

LoopyApp - ERP, WhatsApp and Backend Automation

This system turns ERP sales into automated WhatsApp surveys, captures responses, and stores structured data for analysis — without manual intervention.

Result: each sale triggers a measurable feedback loop, reducing manual work and enabling real-time visibility of customer experience.

Node.js REST APIs Webhooks Azure Functions Azure SQL WhatsApp API Power BI (semantic model)

How it works

The system takes real business events such as sales or invoices, transforms them into a standard order format, validates business rules, schedules message delivery, and stores responses with full traceability.

Business case

Problem

Customer experience was not being measured in real time, surveys were manual or nonexistent, and ERP sales data was disconnected from customer feedback.

Solution

LoopyApp standardizes ERP data, applies business rules, sends WhatsApp surveys automatically, and processes responses through webhooks.

Outcome

Each sale can trigger an automated survey, feedback is stored in a structured way, and customer experience can be analyzed by client, branch, or product.

System flow

How the system processes data from ERP events to structured feedback.

1. Capture

Sales data is read from the ERP, originally through SQL views and later through API-based collectors using incremental control.

2. Standardize

Documents are grouped by invoice and converted into a standard order payload with customer, products, totals, and metadata.

3. Process

The core validates authentication, saves the order, checks campaign rules, validates the phone number, and controls cooldowns and minimum amount.

4. Dispatch

If the order passes validation, it is queued and later dispatched as a WhatsApp survey message.

5. Webhook + Storage

Customer responses, NPS scores, comments, and delivery states are captured through webhooks and stored in Azure SQL.

6. Analytics layer

Reporting-oriented SQL views were created to expose clean analytical tables. Power BI connects to these views to build the semantic model using a snowflake schema, including bridge tables where needed.

Architecture at a glance

  • ERP / External system: source of sales or transactional data.
  • Collector: incremental integration layer that reads APIs and builds a standard sync payload.
  • Core API: receives orders at /api/sync and applies processing logic.
  • Dispatcher: sends pending WhatsApp messages.
  • Webhook handler: receives delivery events and customer responses.
  • Azure SQL: stores orders, messages, responses, and control tables.
  • Analytics layer: SQL views expose structured data for reporting, enabling Power BI to connect and build the semantic model.

Key engineering decisions

Multi-tenant

Processing is isolated by company and branch, preventing data mixing across clients.

Watermark

Only new records are processed, avoiding unnecessary reprocessing.

Idempotency

Each ERP document is checked before processing to prevent duplicates.

Leases

Tenant-level locking prevents concurrent processes from working on the same tenant.

Controlled errors

Retries, circuit breaker behavior, and document-level failures reduce integration risk.

Audit runs

Executions are logged with status, counts, and timestamps for monitoring.

Collector

The collector made the system more flexible by replacing direct ERP database dependency with API-based integration. It fetches new data incrementally, maps it into the standard sync format, and sends it to the core.

Before / After

Before

  • Direct ERP database dependency.
  • Manual or missing surveys.
  • No real-time customer experience measurement.
  • Harder to integrate with large clients.
  • No structured analytical layer for reporting.

After

  • API-based integration through collector adapters.
  • Automated survey dispatch through WhatsApp.
  • Structured response capture with traceability.
  • Multi-tenant execution with duplicate protection.
  • Dedicated reporting layer using SQL views and a semantic model in Power BI.

Technical implementation

These snippets show the kind of backend logic behind the system: receiving ERP events, applying business rules, and processing WhatsApp responses.

Sync endpoint

Receives standardized ERP orders, prevents duplicates, stores the order, and queues the survey flow. 

app.post('/api/sync', async (req, res) => {
  const payload = req.body;

  const exists = await db.checkDocument(payload.erp_doc_uid);
  if (exists) {
    return res.status(200).send('Already processed');
  }

  await db.saveCustomer(payload.customer);
  await db.saveOrder(payload.order);
  await db.saveOrderItems(payload.items);

  await queue.add({
    orderId: payload.order.id,
    campaignId: payload.campaign_id
  });

  res.status(200).send('OK');
});

Business rules

Validates whether an order is eligible before scheduling message delivery. 

if (!isValidWhatsAppPhone(order.phone)) return;

if (order.total < campaign.min_amount) return;

const lastSent = await getLastSurvey(order.customer_id);

if (lastSent && daysSince(lastSent.sent_at) < campaign.cooldown_days) {
  return;
}

await pendingQueue.insert({
  order_id: order.id,
  send_at: calculateDelay(campaign.delay_minutes)

Webhook processing

Captures message status and customer survey responses from WhatsApp. 

app.post('/webhook', async (req, res) => {
  const event = req.body;

  if (event.type === 'message_status') {
    await db.saveMessageStatus({
      messageId: event.message_id,
      status: event.status
    });
  }

  if (event.type === 'survey_response') {
    const parsed = parseSurveyResponse(event.message_text);

    await db.saveSurveyResponse({
      customerPhone: event.from,
      score: parsed.score,
      comment: parsed.comment
    });
  }

  res.sendStatus(200);
});
