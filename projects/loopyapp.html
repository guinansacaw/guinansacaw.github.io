B2B integration platform case study

LoopyApp — B2B ERP, WhatsApp & Data Integration Platform

A B2B platform integrating ERP systems and external data sources with automated WhatsApp workflows, QR interactions, batch processing, operational case management and privacy-aware analytics on Azure.

Node.js Azure Azure Functions Azure SQL Meta WhatsApp Cloud API Key Vault Power BI

The challenge

Connecting fragmented operations without creating fragile integrations.

Problem

Companies often operate with heterogeneous ERPs, external systems, manual follow-up processes and disconnected customer feedback channels.

Solution

The platform connects operational systems to automated WhatsApp workflows, QR interactions, batch processing and analytics while preserving tenant isolation.

Outcome

Operational events become traceable workflows and structured data that can support feedback, cases, reconciliation and reporting.

From operational event to customer interaction

Business events become automated conversations.

System design

One platform. Multiple integration pipelines.

LoopyApp is organized as a multi-pipeline backend platform: ERP and external data enter through controlled adapters, messaging runs through shared Meta infrastructure, and operational events become structured data for case management and analytics.

Integration pipelines

LoopyApp uses several independent pipelines. Collector extends integration options; it does not replace the automatic ERP flow.

ERP Automatic

ERP data moves from an on-prem agent into /api/sync, then through the core, pending work, dispatcher, Meta delivery and webhook feedback.

Collector

External sources or ERP APIs connect through adapters, watermarks, runs, documents and leases, with recovery and reconciliation controls.

Batch Processing

Batch workflows organize lots, recipients, reservations, history and controlled processing for operational messaging scenarios.

QR / Webhook

QR and inbound WhatsApp events carry context into webhook processing, enabling interaction-driven workflows.

Cases

Case components connect responses, activities, responsibilities and notifications for operational follow-up.

Privacy Analytics

Change Tracking, pseudonymization, anonymous aggregates, facts, dimensions, replay and resync prepare data for Power BI consumption.

From interaction to insight

Operational data becomes decision-ready information.

Analytics is treated as a processing layer: Change Tracking, incremental processing, pseudonymization, anonymous aggregates, facts and dimensions, replay and resync prepare data for Power BI. The incremental runtime is described conservatively because its current scope is limited to staging.

Engineering decisions

Key engineering decisions

Multi-tenant

Company, sender and processing context are kept explicit to prevent data mixing across tenants.

Atomic claiming and leases

Work is claimed with controlled ownership windows so concurrent processors do not act on the same unit of work.

Idempotency

Sync payloads, webhook events and pending actions are designed to tolerate retries and duplicate delivery.

Retries and containment

Retries, circuit breaker behavior and failure containment limit the blast radius of external system problems.

Secret management

Meta credentials are referenced through configuration and resolved through Azure Key Vault instead of being embedded in workflows.

Traceability

Runs, documents, send attempts, webhook records, migrations and environment validation support troubleshooting and recovery.
