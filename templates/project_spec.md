# Project Spec

## Nombre del proyecto
Portfolio Optimization — Backend Automation Positioning

## Descripción
Este proyecto mejora el portafolio actual para convertirlo en una herramienta de conversión enfocada en backend automation, API integrations y workflows. El objetivo es pasar de un portafolio técnico descriptivo a uno que comunique valor, enfoque y capacidad real de ejecución para clientes.

---

## ¿Qué hace este proyecto?

- Reestructura el hero para comunicar propuesta de valor y no solo tecnologías
- Reposiciona el portafolio para que destaque proyectos relevantes (especialmente LoopyApp)
- Elimina o alinea proyectos que generan ruido (BI / certificaciones)

## ¿Qué NO hace este proyecto?

- No cambia el stack tecnológico ni la lógica del sitio
- No añade nuevas funcionalidades complejas (dashboard, login, etc.)
- No convierte el sitio en una aplicación — sigue siendo un portafolio estático

## Decisiones arquitectónicas tomadas

> Estas decisiones NO están abiertas a debate durante el desarrollo. Si hay una razón para cambiarlas, se discute aparte.

- **Mantener sitio estático** — simplicidad, velocidad y cero fricción para despliegue
- **Eliminar ruido de data analytics / BI** — alinear todo con backend automation
- **Enfocar narrativa en un proyecto principal (LoopyApp)** — evita diluir percepción de especialización

## Notas adicionales

El problema principal no es técnico, es de posicionamiento y comunicación
El sitio actual ya funciona, pero no está optimizado para conversión
El mayor impacto no viene de agregar más contenido, sino de:
eliminar lo irrelevante
reforzar narrativa
dirigir la atención (hero → LoopyApp → contacto)
Cualquier mejora futura debe evaluarse bajo este criterio:
👉 “¿Esto ayuda a conseguir trabajo o solo hace el sitio más bonito?”
